AI Integration Orchestrator - Folder Structure & Explanation
===========================================================

Project Overview:
-----------------
This project is an AI-driven system that converts a Business Requirement Document (BRD)
into API integration configurations and simulates execution.

Pipeline:
BRD → Parser → Registry → Config Generator → Simulation → UI

Detailed Explanation:
---------------------

1. app/ (Core Backend Logic)
----------------------------

This folder contains the main logic of the system.

------------------------------------------------

1.1 parser/
------------
Purpose: Converts BRD (natural language) into structured JSON.

Files:
- brd_parser.py:
  Uses LLM (Gemini) to extract:
    • Services (KYC, GST, Fraud)
    • Field mappings

- prompt_templates.py:
  Contains prompts used to guide the LLM for structured output.

------------------------------------------------

1.2 registry/
--------------
Purpose: Stores available APIs and their configurations.

Files:
- adapters.json:
  Contains API definitions:
    • Services
    • Versions (v1, v2)
    • Endpoints

- registry_loader.py:
  Loads the registry into Python for use in config generation.

------------------------------------------------

1.3 engine/
------------
Purpose: Converts parsed BRD into executable configuration.

Files:
- config_generator.py:
  • Selects correct service
  • Chooses API version
  • Builds integration configuration

- mapping_engine.py:
  • Creates field mappings (source → target)
  • Used for data transformation

------------------------------------------------

1.4 simulation/
---------------
Purpose: Simulates real API behavior.

Files:
- mock_apis.py:
  Simulates APIs like:
    • KYC verification
    • GST validation
    • Fraud detection

- simulator.py:
  • Applies mapping
  • Calls mock APIs
  • Aggregates results
  • Determines SUCCESS / FAILED

------------------------------------------------

1.5 main.py
-----------
Purpose: FastAPI backend.

- Exposes API endpoints (e.g., /simulate)
- Connects parser → config → simulation

------------------------------------------------


2. ui/
------
Purpose: User Interface (Frontend)

Files:
- app.py:
  Built using Streamlit.
  Allows user to:
    • Enter BRD
    • Run pipeline
    • View outputs:
        - Parsed result
        - Config
        - Simulation output

------------------------------------------------

- sample_config_output.json:

- sample_output.json:
  Example simulation result

System Flow Summary:
-------------------

1. User enters BRD in UI
2. Parser extracts services and mappings
3. Registry provides available APIs
4. Config Generator builds integration config
5. Simulator runs mock APIs
6. Results shown in UI

------------------------------------------------


Key Highlights:
---------------

- AI-driven requirement understanding

- Mock API simulation
- Modular architecture
